# 爬了么 (plgogogo) 产品设计文档

## 项目概述

**产品名称**：爬了么  
**产品定位**：小区爬楼群的运动记录与排行榜小工具  
**目标用户**：小区爬楼群成员  
**核心价值**：降低记录门槛，通过排行榜和成就系统激发运动积极性

---

## 产品目标

1. 让群成员能轻松记录每次爬楼数据（用时、趟数、楼层）
2. 通过多维度排行榜激发竞争意识和参与欲
3. 通过成就系统和可视化统计增强持续运动的动力
4. 零后端成本，纯前端部署，通过分享链接实现数据互通

---

## 用户流程

### 首次使用流程
```
打开链接 → 创建角色（昵称 + 选择头像emoji）→ 设置默认楼层（默认30层，可改）→ 进入首页
```

### 单次爬楼记录流程
```
首页点击"开爬" → 进入计时页（大字体正计时）→ 点击"结束" → 
输入本次趟数（默认1，可改）→ 确认楼层数（预填默认值，可改）→ 保存记录 → 
生成分享链接（可一键复制发到群里）→ 返回首页
```

### 数据分享与聚合流程
```
A 爬完生成分享链接 → 发到微信群 → B 点击链接 → 自动跳转到应用并弹出"导入记录"确认 → 
B 确认后，A 的记录出现在 B 的排行榜中
```

| 页面 | 说明 |
|------|------|
| **首页 / 仪表盘** | 个人数据统计、快速开始按钮、最近记录、爬楼日历 |
| **爬楼中** | 计时器页面，大字体显示已用时间，结束按钮 |

## 功能模块详述

### 1. 角色系统
- 首次进入强制创建角色
- 昵称：2-10个字符
- 头像：从预设 emoji 列表中选择（🏃‍♂️ 🏃‍♀️ 🧗 🦵 🔥 ⭐ 🏆 🥇 等）
- 默认楼层：1-100，默认30
- 角色信息可随时在"我的"页面修改

### 2. 计时记录系统
- 点击"开爬"开始计时（记录开始时间戳）
- 计时页面显示：已用时间（大字体 MM:SS 格式）、当前时间
- 点击"结束"停止计时，自动计算用时
- 结束页面输入：
  - 趟数（number input，默认1，最小1）
  - 每趟楼层数（number input，默认用户设置的默认值）
  - 自动计算总层数 = 趟数 × 每趟楼层数
- 保存后生成分享链接

### 3. 分享链接系统
- 链接格式：`https://<domain>/#/import?d=<base64编码数据>`
- 编码数据包含：版本号、记录数组、分享者昵称
- 使用 pako 进行 gzip 压缩后再 Base64 URL-safe 编码
- 他人点击链接后：
  - 如果无角色，先引导创建角色
  - 然后弹出导入确认弹窗，显示分享者和记录摘要
  - 确认后记录加入本地 importedRecords
  - 已导入的记录不会重复导入（根据记录ID去重）

### 4. 排行榜系统
支持4个维度的排行榜，每个榜单显示前10名：

| 榜单 | 计算逻辑 | 显示字段 |
|------|---------|---------|
| **总趟数榜** | 累计所有记录的趟数 | 昵称、头像、总趟数 |
| **总层数榜** | 累计所有记录的（趟数 × 每趟楼层数） | 昵称、头像、总层数 |
| **速度榜** | 平均每层用时（秒/层），只统计完成过至少3次记录的人 | 昵称、头像、秒/层 |
| **本月活跃榜** | 本月爬楼天数（去重） | 昵称、头像、活跃天数 |

- 当前用户如果在10名外，底部额外显示自己的排名
- 榜单数据来源：myRecords + importedRecords 的合并去重

### 5. 统计与可视化
- **首页仪表盘**：
  - 本月爬楼次数、本月总层数、本月总用时
  - 最近3条记录快速预览
  - 爬楼日历（GitHub 贡献图风格，展示本月每天是否有记录）
- **历史记录页**：
  - 按时间倒序排列的所有记录
  - 每条记录显示：日期、用时、趟数、总层数、速度
  - 支持删除单条记录
  - 支持按月份筛选

### 6. 成就系统
| 成就ID | 成就名称 | 解锁条件 | 图标 |
|--------|---------|---------|------|
| first_climb | 初次尝试 | 完成第1次记录 | 🎯 |
| streak_7 | 坚持不懈 | 连续7天有记录 | 🔥 |
| monthly_30 | 月度达人 | 单月累计30趟 | ⭐ |
| speed_star | 速度之星 | 某次爬楼速度 ≤ 15秒/层 | ⚡ |
| hundred_floors | 百层挑战 | 单次爬楼累计 ≥ 100层 | 🏔️ |
| rank_1 | 排行榜首 | 任意榜单获得第1名 | 👑 |

- 成就解锁时首页弹出 Toast 提示
- 成就墙页面展示已解锁（彩色）和未解锁（灰色）的成就
- 已解锁成就显示解锁日期

### 7. 数据备份与恢复
- **导出**：生成 JSON 文件下载，包含所有本地数据
- **导入**：选择 JSON 文件上传，合并到本地数据（根据记录ID去重）
- 用于换设备时的数据迁移

## 数据模型

```typescript
// 用户配置
interface UserProfile {
  id: string;              // 随机生成唯一ID
  nickname: string;        // 2-10字符
  avatar: string;          // emoji 字符
  defaultFloors: number;   // 默认每趟楼层数，默认30
  createdAt: number;       // 创建时间戳
}

// 单次爬楼记录
interface ClimbRecord {
  id: string;              // UUID
  userId: string;          // 记录所属用户ID
  userNickname: string;    // 记录时的昵称（快照）
  userAvatar: string;      // 记录时的头像（快照）
  startTime: number;       // 开始时间戳
  endTime: number;         // 结束时间戳
  duration: number;        // 用时（秒）
  laps: number;            // 趟数
  floorsPerLap: number;    // 每趟楼层数
  totalFloors: number;     // 总层数 = laps * floorsPerLap
  createdAt: number;       // 记录创建时间戳
}

// 分享数据包
interface SharePayload {
  v: number;               // 数据格式版本，当前为1
  records: ClimbRecord[];  // 要分享的记录
  from: string;            // 分享者昵称
}

// 应用状态（localStorage 存储）
interface AppState {
  profile: UserProfile | null;
  myRecords: ClimbRecord[];
  importedRecords: ClimbRecord[];
  achievements: string[];   // 已解锁成就ID列表
}
```

## 技术架构

### 技术栈
- **框架**：React 18 + TypeScript

## 设计原则

1. **移动端优先**：所有设计针对手机微信内置浏览器优化
2. **极简操作**：核心流程（开爬→结束→保存）不超过3步
3. **即时反馈**：计时器大字体、成就解锁动画、保存成功提示
4. **零学习成本**：不需要说明书，首次使用有引导
5. **视觉激励**：排行榜排名变化、成就徽章、爬楼日历可视化
